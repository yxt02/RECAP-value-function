日期：2026-09-21。范围是当前分布价值模型的训练、缓存、评估入口，以及新增离线优势计算流程。使用本机 `value_function` conda 环境与已有 `checkpoints/optimized/best_model.pt`，没有覆盖或重新训练 checkpoint。

## 发现并修复的问题

| 问题 | 影响 | 修复 |
|---|---|---|
| `run_test.sh` 仍调用 `tests/` 中已经移动的脚本 | 一键评估无法启动 | 改为 `submodules/`，使用参数数组调用代替 eval，拒绝未知参数与缺失 checkpoint 参数 |
| `split_metadata`、接管阴影 `shade` 遗漏 numpy 导入，评估函数遗漏 logger | 实际评估或绘图 NameError，`--help` 无法发现 | 补齐模块依赖，增加轨迹元数据与阴影回归测试，真实执行完整测试集与报告渲染 |
| 分布模型 checkpoint 仍声明 scalar 架构 | 新旧模型身份混淆，旧评估不支持 num_bins | 新 checkpoint 使用 categorical 名称；读取时检查档位和输出权重形状，兼容旧错误名称，但拒绝真正标量权重 |

| `--checkpoint` 没传给缓存检查 | 指定其他模型时可能仍检查默认模型 | 缓存检查新增 checkpoint 参数并读取其保存配置，一键入口贯通该参数 |
| README 仍描述标量回归、MSE 早停，并把旧测试指标叫当前结果 | 模型结构、训练目标与质量结论易误读 | 更新分布期望、CE 早停、当前训练结果和历史记录标识 |
| `calculate_advantage.py` 尚无完整实现 | 无法导出正式优势标签 | 实现逐帧推理、轨迹内 N 步奖励与终点处理、固定阈值标签、全量/指定轨迹选择、复用价值、多跨度曲线和接管对比 |

此前缓存启动问题的证据与修复见 [缓存恢复记录](cache_startup_recovery.md)。当前缓存构建关闭 persistent workers，并采用 cache_num_workers=0；测试特征缓存已顺利完成提取、写盘、校验和加载，约 215 帧/秒。

## 已执行的验证

1. **29 项单元测试通过**：包括成功/失败终点、短轨迹、折扣、50 步公式、精确回报的零残差、阈值相等归入 disadvantage、接管起点与缺失标记、分档边界、checkpoint 兼容和重构入口。
2. **完整 test**：37 条轨迹、34,759 帧，50 步、阈值 0，输出 34,759 条评分。
3. **全部数据**：327 条轨迹、310,031 帧，train 246,913 / val 28,359 / test 34,759 帧，输出相同数量的 50 步评分及 327 张轨迹图。
4. **复用预测**：不加载模型，重新计算 test 的 1/10/50 步、阈值 0.01，共 104,277 条评分。复用前后逐帧价值完全一致；all 中 test 的价值与单独 test 完全一致。
5. **独立数值核对**：用奖励累计和重新计算所有导出评分，与脚本的逐步累加实现核对，误差在 1e-12 内；标签、唯一键、文件哈希和 HTML 图片引用检查通过。
6. **失败批次**：2026.09.16_error 的 100 条轨迹均保留失败覆盖，无成功标记回退。checkpoint SHA256 前后未变。
7. **旧评估流程**：96 帧缓存/在线推理及 checkpoint 重载检查通过；随后完成全 test 评估及 37 条轨迹的报告渲染。修复后入口可用。
8. 人工检查成功轨迹、失败轨迹及接管汇总图，中文、曲线、阈值及接管标记可读。

## 当前结论及限制

优势推理、标签导出和接管对比的离线输入输出流程已跑通。默认 test 且不在测试集自动选择阈值。人工接管不是错误真值，正负优势也不直接等同于动作好坏。

本次未更改现有模型参数。它使用旧分档规则训练；修正分档只影响下一次训练，不能把修正后的训练行为追溯算作当前 checkpoint 的结果。当前 checkpoint 仍可按自己保存的档位中心输出价值，用于验证流程。

作为辅助检查，当前 checkpoint 的 test MSE 约 **0.02372**，训练集拟合的“数据批次 + 帧序号”对照约 **0.02250**；因此本次不能宣称模型价值信号优于简单对照或适合直接指导策略训练。曲线仍可见逐帧波动。

尚未实现 π 策略、优势条件动作生成、在线交互或语言条件价值模型。实现仅借鉴 RECAP 流程，运行不依赖 RLinf/Ray。评估目前仍要求原 CUDA/BF16 环境；优势脚本的 CPU 分支未在本次真实数据验收中单独执行。

使用方法与逐字段输入输出合同见 [优势计算说明](advantage.md)。
