## 逐项差异与改进

### 1. 图像尺寸：直接拉伸，改为等比例缩放后补零

**原来**：将图像直接变为 `224×224`。当原图不是正方形时，宽、高缩放比例不同，物体形状和场景中的相对几何关系会发生形变。

**现在**：保持原长宽比缩放，使最长边达到 224，再居中补黑边至 `224×224`。例如 `640×480 → 224×168 → 上下各补 28 像素`。

**作用**：避免非等比例拉伸，保留物体形状、长宽比例和相对几何关系。补边会平移内容，缩放也会损失部分细节，因此不能称为完全保留原始像素坐标。

**细节**：补零发生在归一化之前；当前均值和标准差均为 0.5，黑边进入模型时对应 −1，而不是 0。

### 2. 图像增强：固定预处理，改为仅训练时随机增强

**原来**：训练使用固定预处理，同一帧在不同轮次的输入基本相同。

**现在**：先等比例缩放补边，再进行随机裁剪、缩放回原尺寸、旋转和颜色扰动。裁剪保留约 95% 的边长，旋转范围约为 ±5°；亮度系数为 0.7–1.3，对比度为 0.6–1.4，饱和度为 0.5–1.5。验证和推理不启用随机增强。

**作用**：增加训练输入变化，降低对固定位置、光照和颜色的依赖。训练增强会主动改变部分几何信息，不能与基础缩放的比例保持混为一谈。

**细节**：代码按相机名称是否包含 `wrist` 判断是否跳过裁剪和旋转；本次 `cam2/cam3/cam4` 都不满足该跳过条件。

### 3. 相机输入：单路视角，改为三路视角

**原来**：正式模型只输入 `cam2`，只能从一个视角判断场景状态。

**现在**：输入 `cam2/cam3/cam4`，三路共享同一个视觉编码器，分别编码后按固定顺序拼接。（RLinf采用的是单一视角相机数据 但是考虑到手腕相机对是否抓取合理起到了作用 故加入 但是具体位置分布权重 性能效果还需评估或者进一步设计）

**作用**：提供更多视角线索，有机会缓解单视角遮挡或关键状态不可见的问题。是否改善失败识别，需要实际对照验证。

**细节**：当前没有额外的独立相机身份嵌入，主要依靠固定拼接顺序和序列位置区分各路图像。

### 4. 视觉表示：平均特征向量，改为完整图像块序列

**原来**：SigLIP 输出图像块特征后沿图像块维度取平均，每帧得到一个 1152 维向量，再送入价值头。

**现在**：每路 `224×224` 图像按 `14×14` 划分，保留 256 个图像块 token；三路共 768 个。每个 token 从 1152 维投影到 640 维，保留整个序列供后续注意力读取。

**作用**：减少过早平均造成的信息压缩，让后续网络能够分别读取局部区域。旧特征也包含视觉编码器处理后的空间信息，但后续价值头无法直接选择不同图像块。

### 5. 任务文字：不参与价值预测，改为实际网络输入

**原来**：旧平均特征模型没有使用任务文字，Gemma 也没有参与价值预测的前向计算。（因为原来考虑是单一任务进行流程的测试，如果加入prompt 都是一样的 那就相当于给网络整体加了一个偏置 按道理来说是没什么用）

**现在**：将任务文字整理为 `Task: ….`，分词并嵌入，与图像 token 一起组成前缀。（为后续多任务做准备 也尽可能靠近RLinf和pi*0.6原文）

**作用**：使价值模型具备任务条件输入，并对齐图像与文字的处理接口。

**细节**：当前数据为单任务，文字基本固定，因此它不能提供区分不同帧的新信息；尚未验证多任务条件化效果。

### 6. 融合网络：线性投影和 MLP，改为 Gemma Transformer 前缀

**原来**：平均视觉特征经过线性投影和 MLP，直接输出价值分布。

**现在**：图像 token 与文字 token 进入 Gemma3-270M 的 18 层骨干，生成逐层 Key/Value（KV）表示，供价值专家读取。

**作用**：增加利用注意力处理图像与文字信息的能力，不再仅对一个平均向量进行映射。这是更强的表达能力，不等同于已经证明预测更准确。

```text
旧版：cam2 → SigLIP → 图像块平均 → 1152→640→256 的投影/MLP → 201 档

新版：cam2/3/4 → SigLIP → 768 个图像块 → 每个投影至 640 维
                                     + 32 个文字位置
                                     → Gemma3 18 层前缀 KV
                                     → 18 层价值专家 + CLS 查询
                                     → 201 档概率 → 连续价值期望
```

### 7. 价值头：小型 MLP，改为独立 Transformer 专家

**原来**：投影层和 MLP 价值头合计约 95 万可训练参数。

**现在**：使用独立的 Gemma 价值专家和一个可学习的 CLS 查询。专家读取前缀 KV 后，将最终 CLS 表示投影到 201 档价值分布。

**作用**：提高价值头读取前缀表示和处理复杂关系的能力，同时增加计算量、显存需求和过拟合风险。

**细节**：当前配置名为 `gemma_50m`，隐藏维度 384、18 层；去掉词嵌入后的专家实际有 63,715,200 个参数，约 6372 万。该数值不包含视觉骨干、Gemma3、图像投影、CLS 和输出投影。专家为新初始化并通过价值任务训练的模块，不是一份预训练价值模型。

### 8. 专家与前缀层对应：4 层读取，改为默认 18 层读取

**原来（中间版本）**：`gemma_1m` 专家有 4 层、隐藏维度 128，只读取前缀前 4 层 KV，但仍执行完整的 18 层前缀。

**现在**：默认 `gemma_50m` 专家有 18 层，第 `i` 层读取前缀第 `i` 层 KV。若使用 4 层调试专家，只执行前 4 层前缀，跳过未读取的后续层。

**作用**：默认结构覆盖全部 18 层前缀表示；小专家模式避免执行没有被价值头使用的层。

**细节**：最后一个被读取的前缀层通过 KV 路径影响价值，前缀最后输出并未直接送入价值头，不能据此声称每个骨干参数都有价值损失梯度。

### 9. 训练范围：冻结视觉骨干，改为微调相关模块

**原来**：冻结 SigLIP，只更新后面的投影层和 MLP。

**现在**：视觉编码器、Gemma 骨干、价值专家的冻结开关均关闭，价值损失可以沿相关计算路径反向传播。

**作用**：使视觉和融合表示能够适应机器人价值任务，代价是更重的训练和更高的过拟合风险。本次第一轮之后验证指标恶化，不能认定端到端微调已经改善泛化。

### 10. 价值分档：单档硬标签，改为相邻两档软标签

**原来**：将连续目标放入一个档位，以单个类别标签计算交叉熵；推理采用 201 个等宽区间的中心值。

**现在**：使用均匀覆盖 `[-1,0]`、包含两端点的 201 个价值位置，相邻间隔为 0.005。目标按距离分配给相邻两档，使用 two-hot 交叉熵训练；推理仍取概率加权期望。

**作用**：保留连续目标在相邻档之间的位置，减少跨档时监督突然变化的问题。例如目标 −0.327 位于 −0.330 与 −0.325 之间，可分别分配 0.4 和 0.6 的权重。

**细节**：旧版已经是 201 档分布模型，本次新增的是分档位置与软标签方式，不是首次引入分布输出。新旧交叉熵不能直接按同一种损失解释。

### 11. 价值归一化：固定尺度，改为只用训练集确定尺度

**原来**：根据数据合同，将回报固定除以 4000。

**现在**：只使用训练划分最小回报的绝对值，本次为 3856；将尺度保存到 checkpoint，并供验证、测试和优势计算共同使用。超出支持区间的目标截断到 `[-1,0]`。

**作用**：避免根据验证或测试数据重新确定归一化尺度，并确保价值与优势计算中的奖励项使用一致单位。

### 12. 文字长度和掩码：排除无效位置，减少补齐开销

**原来（Gemma 版本）**：文字最大长度先为 50，后调整为 200；虽然有掩码，仍需处理更长的张量和注意力形状。

**现在**：最大文字长度为 32，当前任务实际约 16 个 token。通过文字及相机有效性掩码排除无效位置，位置编号按有效 token 计算。本次前缀张量有 `768+32=800` 个位置。

**作用**：在不截断当前任务有效信息的情况下，减少大量补齐位置带来的计算开销。


### 13. 数值精度：BF16 配合部分 FP32 参数

**原来**：旧模型已经使用 BF16。

**现在**：继续使用 BF16，同时将视觉 patch/位置嵌入及部分归一化参数保留为 FP32；输出 logits 和损失中的关键计算使用 FP32。

**作用**：兼顾显存、速度和数值稳定性。


### 14. 梯度检查点和 KV：修复重计算及缓存复用

**原来（中间版本）**：主要设置外层检查点标志，在本机依赖版本中没有实现预期的完整重计算路径。

**现在**：视觉使用标准检查点接口，前缀与专家分别进行非重入分段重计算；阶段间传递 KV 张量，为专家重建独立缓存，避免追加或重计算时修改同一份缓存。

**作用**：提供可用的低显存训练路径，并避免 KV 可变缓存与重计算相互干扰。

**本次设置**：正式训练关闭梯度检查点。batch 8 的显存占用有余量，短测显示关闭重计算更快；该修复属于可用能力，不是本轮开启的加速项。

### 15. 优化器：统一小头学习率，改为模块分组

**原来**：只训练小头，统一学习率为 `1e-4`；预热 200 步后进行余弦下降。

**现在**：视觉学习率为 `5e-5`，Gemma 为 `5e-5`，专家、图像投影、CLS 和价值投影为 `1e-4`。预热 500 步后保持设定学习率，当前没有余弦下降。

**作用**：为预训练骨干和新初始化模块设置不同更新幅度。

**细节**：权重衰减仍为 0，梯度范数裁剪为 1.0。持续保持学习率可能与后续过拟合有关，但没有单独对照实验，不能直接确定因果。

### 16. 特征缓存与并行：缓存小头训练，改为在线编码和双卡 DDP

**原来**：冻结视觉编码器且没有随机增强，可以先缓存平均特征，再用较大 batch 训练小头。

**现在**：视觉权重会更新、图像有随机增强，每个 batch 在线编码。双卡 DDP 中，每卡保留完整模型并处理各自的数据，反向传播同步梯度；验证使用不重复分片，主进程写 checkpoint。

**作用**：支持端到端微调和两张 GPU 并行计算。固定的旧平均特征缓存不能用于当前训练。旧架构兼容缓存另升级为 v3，记录新的预处理身份并拒绝缓存随机增强。

**本次设置**：每卡 batch 8、梯度累积 1 次，全局有效 batch 为 16；每个进程的训练和验证加载器各使用 2 个 worker，按 batch 读取图像，视频句柄缓存有上限，不一次性将全部图像装入显存。

## 实测改进与仍未解决的问题

### 历史结果参考

旧模型测试有 34,759 帧，新模型测试有 36,896 帧，归一化尺度分别为 4000 和 3856。因此下表只能描述历史观察，不是同一数据、同一尺度下的严格 A/B 对照，也不能归因到某一个改动。

| 指标 | 旧版报告 | 本次新版 | 解释 |
|---|---:|---:|---|
| 相邻预测波动 / 真实一步回报变化 | 约 72 倍 | 8.2 倍 | 抖动明显减少，仍有噪声 |
| 全部测试帧 MSE | 0.02372 | 0.02393 | 未显示总体改善 |
| 成功轨迹 MSE | 0.01008 | 0.00615 | 有改善迹象 |
| 失败轨迹 MSE | 0.04560 | 0.05283 | 未显示改善 |

本次模型 MSE 为 0.02393，而在同一测试集上、只用训练集拟合的“数据批次＋当前帧序号”对照为 0.01978。模型点估计高约 21%，按轨迹配对重采样的差异区间仍跨过零，现有结果不能证明模型优于该对照。

两个成功/失败混合批次中的 3 条失败轨迹占测试帧数约 8.9%，却贡献约 67.5% 的总平方误差。需要重点排查失败状态识别和对采集场景、进度线索的依赖。高趋势相关性不能代替准确的价值水平。

### 训练效率与过拟合

同一新版网络最初的 batch 1 运行每轮约需 20 小时；调整 batch、文字长度、数据加载和检查点开关后，本次每轮训练约需 2 小时 48 分钟，峰值保留显存约 20.1 GiB。该速度比较针对同一新版网络的运行配置，不是旧小头架构与新架构的对比。

第 1–4 轮训练交叉熵从 3.290 降至 1.676，验证交叉熵却从 3.110 升至 3.938，出现明显过拟合；连续 3 轮未改善后早停，最终保留第 1 轮模型。

### 优势标签的解释边界

旧报告使用训练集优势分数的分位阈值，并导出全部划分；本次后台流程使用固定零阈值，导出 test 划分。两者都支持接管帧强制置正。这属于实验和导出配置差异，不是网络结构变化，正例比例不能直接用于判断模型是否改善。

本次导出通过了行数、唯一键和有限值检查，但验证文件仍标记 `model_quality_validated=false`。尚无人工动作质量真值或策略闭环结果证明这些标签能够提升策略表现。

## 本次没有改变的部分

- 非终止奖励仍为 −1，成功终止为 0，失败终止为 −2000，折扣因子为 1。
- 模型仍逐帧读取图像，没有新增多帧视频或时序记忆模块。
- 关节状态和动作仍不作为价值网络输入。
- 没有新增时间平滑损失；曲线更平滑属于观测结果，尚未通过消融实验定位原因。
- 原有按轨迹划分训练、验证和测试的方式仍用于评估；当前没有策略训练或机器人闭环性能对比。
- 后台启动可抵御终端断开，但尚无服务器重启后自动续训机制。
