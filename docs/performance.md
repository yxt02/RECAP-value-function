# 本机训练性能记录（2026-09-17）

环境：i9-14900KF（24 核 / 32 线程）、31 GiB RAM、RTX 4080 SUPER 16 GB、NVMe；已有 `value_function` conda 环境。PyTorch 2.7.1 + CUDA 12.6，Transformers 4.57.6。桌面进程占用部分 GPU 显存。没有重装环境，也没有终止用户的其他程序。

## 已修复的问题

- 训练入口原来忽略 episode split，用整个文件夹训练/验证；现在统一按现有 train/val manifest 加载，test 不参与调参。
- 原 forward 没用到 Gemma，却加载了它的权重；现在仅加载实际参与计算的 SigLIP。
- SigLIP 的第一个 patch 不是 CLS token；现在对所有 patch 取均值，并按配置拼接 camera 特征。
- 原 scalar 输出是 `[-1,1]`，现在与 return 合同一致为 `[-1,0]`；最终 tanh 用 FP32，避免 BF16 输出量化掩盖较小的标签差异。
- 冻结 encoder 始终保持 eval/no_grad。取消训练循环中的周期性 gc/empty_cache。
- 图像训练不再为每个随机帧反复读完整 parquet；预载 task/frame 索引。限制 FFmpeg、OpenCV、BLAS 的线程，避免每个 worker 再开几十条线程。
- 冻结、无随机增强的视觉特征只编码一次，带指纹、校验和及原子发布；已缓存特征可以驻留 GPU。
- 短测试通过 batch sampler 限制实际请求的 batch，而非在有视频解码预取时突然 break；多 worker 探针已验证正常退出。
- checkpoint 只保存需要训练的头和恢复所需配置/优化器信息，不重复写冻结视觉权重。

这些更改针对当前视觉标量基线。语言条件、Gemma critic、201-bin 分类损失仍未实现，不能据此声称完成了完整 RECAP 复现。

## 测量范围

GPU 探针使用 GPU 上的随机输入，预热 3 步、测量至少 12 步且至少约 1,024 个样本（各组约 3.8–8.4 秒），包含前向/回归头反向/优化器更新；不包含视频解码。旧实现和新实现的 pooling/输出范围也不同，因此下表不是单独测量 BF16 的因果效果，更不是精度对照实验。

| 实现 | batch | 样本/秒 | PyTorch 峰值 allocated GiB |
|---|---:|---:|---:|
| 优化前 FP32 | 2 | 121.8 | 2.65 |
| 当前 BF16 | 8 | 262.1 | 0.89 |
| 当前 BF16 | 16 | 273.0 | 0.95 |
| 当前 BF16 | 32 | 261.1 | 1.07 |
| 当前 BF16 | 64 | 243.6 | 1.31 |
| 当前 BF16 | 128 | 243.5 | 1.79 |

选择本次吞吐最高的 batch 16。不能据此断言 16 在所有模型、相机数量和机器负载下最优。完整缓存期间 GPU 利用率实测 100%，功耗约 274 W；显存不满并不意味着计算资源闲置。

数据加载探针使用实际训练 split 的均匀子集，随机取帧，batch=32，4 个 warmup batch 后测 24 个 batch。正常退出的复测结果：0 / 2 / 4 / 8 worker 分别约 211 / 396 / 743 / 1141 帧/秒。复测后半段与完整缓存有短暂重叠，属于本机负载下的结果，并非隔离实验。4 worker 已超过 encoder 需求且启动开销小于 8 worker，故默认使用 4。缓存特征阶段不再需要视频 worker。

当前 train/val 的失败帧占比分别为 38.8% / 40.0%，保留自然采样，未额外过采样。只输出训练标签均值的常数模型，其验证 MSE 为 0.0735253；后续报告可据此判断训练是否学到有效信息。

## 完整缓存与回归头训练

完整 train/val 缓存已生成：246,913 / 28,359 帧，编码及落盘阶段分别 907.2 / 113.3 秒，总计约 17.0 分钟（整个命令约 17.2 分钟）。两组 features/targets 文件合计 635,328,288 bytes，即 605.9 MiB。缓存构建日志为 `artifacts/performance/prepare-cache.log`。

回归头基准使用全量 train 特征，先完整预热一轮，再测两轮；包含真实打乱、MSE、反向、梯度裁剪和 optimizer step。**不包含首次编码、进程启动和 checkpoint 写盘**。

| batch | CPU 特征加载：秒/轮 | 显存驻留：秒/轮 |
|---|---:|---:|
| 256 | 1.345 | 0.679 |
| 512 | 1.040 | 0.344 |
| 1024 | 0.818 | 0.188 |
| 2048 | 0.971 | 0.090 |

随后使用真实 train/val、固定 seed=42 对 3 个 batch 进行有上限试训：epoch 上限 40、总步数上限 5000、warmup 200、LR 1e-4、每轮完整验证、4 轮未达到 1e-5 的改善则早停。

| batch | 实际轮数 / steps | 最佳验证轮 | 最低验证 MSE |
|---|---:|---:|---:|
| 512 | 11 / 5000 | 10 | 0.01179747 |
| 1024 | 20 / 4840 | 16 | 0.01160752 |
| 2048 | 20 / 2420 | 16 | 0.01200945 |

选择 batch=1024：当前单 seed 试验中验证误差最低，训练时间已很短，进一步追求 2048 的纯吞吐收益有限。这是本数据与本模型上的可复查选择，不是全局最优或多 seed 显著性结论。

最终设置 `num_epochs=24`、`max_total_steps=5000`（242 steps/完整轮，最多约 20.7 遍）、`warmup_steps=200`（总预算的 4%）、`early_stopping_patience=4`、`min_delta=1e-5`。24 轮是保护性上限，实际由总步数及早停决定，避免固定跑旧的 50 轮。

最终配置已实际跑完：第 20 轮、第 4840 步触发早停；保留第 16 轮 checkpoint，验证 MSE=0.01160752。常数基线为 0.0735253，测试集没有参与选择。这是当前视觉基线的验证误差，不能直接解释为机器人任务成功率。

20 轮累计训练循环 4.02 秒，累计验证 0.08 秒；日志从配置输出到早停约 13.4 秒，另有解释器启动开销。大部分额外时间用于模型/数据指纹及缓存 SHA 校验，而非训练。不能把 0.19 秒/轮误解为包含首次 17 分钟编码或完整进程启动的时间。

模型保存在 `checkpoints/optimized/best_model.pt`，约 10.4 MiB（包含 optimizer）；实际配置和指标在同目录。它沿用本地 SigLIP 权重，只保存可训练回归头，不覆盖旧入口的 checkpoint。

## 最终核验

- 13 项 CPU 回归/集成测试：包括真实数据 split 隔离、失败 episode 26、22 维状态/动作、processor 对齐、缓存指纹/损坏/中断清理、全局预算与早停边界。
- 真实全量缓存完成并通过 SHA256/形状检查；训练集全部特征均有限。
- 抽取 6 个位置（包括不同数据批次边界）共 96 帧，缓存等于对应在线特征的 FP16 表示。encoder 的均值特征输出实际是 FP32，FP16 存储最大绝对量化差异为 0.003845；这是特征量化误差，不是 value 误差。冻结模型的在线 forward 已统一 FP16 特征精度，在这些样本上在线/缓存预测差为 0，checkpoint 重载预测也一致。
- 缓存路径与在线多 worker 路径均跑真实前向、反向及参数更新冒烟测试；日志在 `artifacts/performance/cached-smoke.log` 与 `online-smoke.log`。
- 原用户训练脚本/配置快照保存在 `submodules/reference/`；原始数据、旧 checkpoint、`nohup.out` 未作删除。
