# 当前 checkpoint 的测试结果与使用边界

本报告只讨论本机现存的 **201 档分布价值模型**，不混用旧标量 checkpoint 的实验数字。这里的“通过”指输入输出、数据关联和优势计算流程通过检查；尚无证据证明价值或正负优势标签能提升策略表现。原始评估和优势产物位于 `.gitignore` 排除的 `artifacts/`，远程仓库只有生成它们的代码与本报告。

## 实验身份与数据

- checkpoint：`checkpoints/optimized/best_model.pt`，SHA256 `f339776b0711eda819f0579e16e62a45a22cd90cdc1da2e0469dc09a210a3413`。文件内架构文字仍是旧的 `scalar` 名称，但保存的权重是 201 档输出；加载器按实际权重检查兼容性。
- 训练：train 260 条 / 246,913 帧，val 30 条 / 28,359 帧；第 14 轮 / 3,388 步早停，最佳 checkpoint 来自第 10 轮 / 2,420 步，验证 CE 为 **3.31683**。模型以验证 CE 选取，未用 test 调参。
- 独立测试：test 37 条 / 34,759 帧，其中成功 24 条、失败 13 条。评估文件 `artifacts/evaluation/run_20260921_195918/metrics.json` 的 checkpoint 哈希与现存文件一致。
- 视觉输入：冻结 SigLIP2，使用 `cam2` 单相机、patch 特征平均与约 95 万可训练参数的分布价值头；不读取任务文字、关节状态。价值期望范围在 `[-1,0]`。
- 训练这份 checkpoint 时，目标分档使用了当时的旧规则；现行源码已修改分档。对完整 train 缓存的 246,913 个目标，两套规则有 **70,082 个（28.4%）**落在相邻档位。代码修正不会追溯改变这份权重。

## 独立测试：总体与不同数据

下表 MSE 越低越好。“批次＋帧序号”对照只在 train 上拟合，再应用到 test；它不读取测试轨迹的长度或成败标签。数值取自同一份 `metrics.json`，不是旧标量模型的报告。

| test 范围 | 轨迹 / 帧 | 当前模型 MSE | 简单对照 MSE |
|---|---:|---:|---:|
| 全部 | 37 / 34,759 | **0.02372** | **0.02250** |
| 成功 | 24 / 21,417 | 0.01008 | 0.00429 |
| 失败 | 13 / 13,342 | 0.04560 | 0.05174 |
| `2026.09.08` | 11 / 7,224 | 0.00027 | 0.00016 |
| `2026.09.15` | 3 / 3,539 | 0.03379 | 0.03737 |
| `2026.09.15_2` | 13 / 14,080 | 0.04806 | 0.04381 |
| `2026.09.16_error` | 10 / 9,916 | 0.00264 | 0.00321 |

模型总体 MSE 比对照高约 **0.00121**。按轨迹配对重采样 4,000 次，“模型 MSE－对照 MSE”的 95% 区间为 **[-0.00587, 0.00769]**，跨过 0；现有 37 条测试轨迹不足以支持它比该对照更好的结论，也不足以断言它在总体上必然更差。整体相关指标会受不同数据批次的回报水平影响，不能代替逐轨迹质量判断。

对优势差分更直接的检查也不理想：排除终止转移后，相邻两帧预测价值的平均绝对变化约 **0.01796**，对应真实一步回报变化为 **0.00025**，相差约 **72 倍**。预测曲线的局部波动可能改变 50 步差分的正负号。MSE 和这种波动都只是诊断，尚没有人工动作质量真值或策略训练结果来验证标签。

## 已导出的标签是什么

`artifacts/advantage/recap-all/` 用这份 checkpoint 给全部 327 条轨迹、310,031 帧打了 50 帧优势分数，并用 train 的优势分数第 70 百分位 **0.00852864** 作为阈值。分位模式中 `A >= 阈值` 为正例；`intervention=1` 的帧也被强制置正。验证文件确认帧数、唯一键、有限值和导出行数，明确写着 `model_quality_validated=false`。

| 原始数据批次 | 全部分数正例比例（接管覆盖前） | 标记接管的帧比例 | 最终正例比例 |
|---|---:|---:|---:|
| `2026.09.08`，纯遥操作成功批次 | 14.4% | 0% | **14.4%** |
| `2026.09.15` | 38.6% | 35.4% | 57.5% |
| `2026.09.15_2` | 41.3% | 30.6% | 58.1% |
| `2026.09.16_error`，全部失败 | 26.1% | 46.8% | **58.4%** |

接管比例与分数正例比例可重叠，不能相加解释最终比例。失败轨迹中某一帧有正优势并不构成数学错误；接管动作也可能比接管前更好。但这组分布说明：**当前标签不应仅凭“流程通过”就作为可靠策略监督信号。** 尤其是纯遥操作成功批次的低正例比例、失败批次的高正例比例，需要结合数据来源和人工片段逐条核查。这里的 `2026.09.08` 未作为独立 `sft` 类型强制置正；这与所参考的 RLinf 示例流程不同。

## 如何重建并解释结论

```bash
bash run_test.sh --checkpoint checkpoints/optimized/best_model.pt
python scripts/calculate_advantage.py --split all --label-rule percentile \
  --percentile 30 --reference-split train --output artifacts/advantage/new-audit
```

首次运行会读取本地视频并构建或校验特征缓存；第二条命令重新计算所有轨迹，耗时取决于缓存状态。结果目录中的 `manifest.json` 记录 checkpoint 哈希、划分文件哈希与标签规则；读取前应确认 `status=complete`。已完成的轨迹图可以帮助定位具体片段，但接管前后统计是描述性比较，不是因果或动作正确性证明。

本仓库目前完成数据适配、价值预测、离线优势计算和标签导出；未训练带优势条件的 π 模型，也未做真机或仿真性能对比。下一阶段若要评价标签或改模型，应先固定同一份数据划分与评估协议，再做有针对性的对照实验；“更大网络是否改善结果”尚未通过实验验证。
