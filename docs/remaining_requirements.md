# 剩余工作：优势评分、条件标签与轨迹对比

本文定义当前价值函数工程下一阶段需要实现的功能、接口和验收标准，可直接作为开发任务清单。目标是用已有数据和价值模型输出逐帧评分、`advantage` / `disadvantage` 标签，并支持查看和比较；不要求这些评分已经准确反映机器人动作质量。

文档日期：2026-09-21。此文是历史设计草案，部分命令与默认值已被实现方案替代。当前可运行接口见 [优势计算说明](advantage.md)，验收范围和剩余限制见 [重构审阅](refactor_review.md)。默认 split 已改为 test，以便先检查未参加训练的数据。

## 1. 目标与范围

完成如下独立离线流程：

```text
现有轨迹 + 回报合同 + 当前价值 checkpoint
    → 逐帧价值预测
    → 多步优势评分
    → 阈值划分与条件标签
    → 轨迹汇总、对比和可视化
    → 自动检查与验收报告
```

本次不接入 π 策略模型，不训练策略，不生成机器人动作，不做真机或仿真交互。无需等待新的策略训练数据或 π 权重。RLinf 仅参考其优势计算、边界处理和标签组织思路，不引入 RLinf、Ray、Worker 或分布式训练框架。

模型输出称为“模型价值评分”和“模型优势评分”。本次通过表示数据关联、计算和输出正确，不表示价值信号已经可靠，也不表示完整 RECAP 策略学习已完成。

## 3. 必须实现的功能

### F1：按轨迹选择数据并生成价值评分

支持按 split、数据集名和轨迹编号选择输入。默认仅选择 train；使用 val/test 需显式指定。轨迹选择采用 `(dataset_id, episode_index)`，不能只用可能跨批次重复的编号。

输入必须包含原始图像、帧编号、时间戳、任务标识，以及与当前模型匹配的回报合同。加载 checkpoint 后遵循其中的相机顺序、图像预处理、特征精度和归一化约定。当前是 cam2 图像模型，不能在不匹配时静默增加相机或改变预处理。

每条所选完整轨迹的每个有效帧输出一个价值 `V_t`。预测值应为有限数，符合当前模型 `[-1,0]` 的支持范围。选择小样本时按完整轨迹选择，不能因为截取前若干帧而把截断处当成终止。

缓存身份至少包含权重、数据选择、预处理和精度。模型在需要时推理一次；修改优势前瞻长度或标签阈值时复用价值结果，不重新编码视频。

### F2：计算包含轨迹末尾的多步优势

把计算实现为独立、可测试的纯函数，不依赖 GPU 或绘图。普通帧、最后一帧、失败终止和短轨迹使用同一明确规则。

设一条完整轨迹有 L 帧，帧编号为 `0…L−1`。`r_t` 是合同赋给第 t 帧的奖励，`V_t` 是该帧价值，N 为前瞻帧数，S 为回报尺度：

```text
k = min(N, L − t)
R = sum(gamma**i * r[t+i] for i in range(k))
next_value = V[t+k]，若 t+k < L
next_value = 0，若已到达真正的轨迹终止边界
A[t] = R / S + gamma**k * next_value − V[t]
```

当前合同为 `gamma=1`、`S=4000`；非终止帧奖励 −1，成功终帧 0，失败终帧 −2000。奖励只除以尺度一次，不能把原始奖励与归一化价值直接相加，也不能额外重复施加失败惩罚。

必须区分“到达有已知结局的轨迹终点”和“数据缺失或人为截断”。后者没有下一状态时标记为无效并给出原因，不用零价值假装终止。当前数据未单独标明截断时，只允许使用合同确认完整的轨迹；无法确认的输入拒绝进入正常标注流程。

默认 N=10，支持同时计算 1、10、30 等多个正整数跨度。时间含义以 `N/fps` 展示；不同帧率不能直接当作相同时间跨度。每个跨度保留实际 k、是否到达终点和下一价值的来源。

### F3：输出 advantage / disadvantage 标签

保留原始优势分数与条件标签，两者不可混为一谈。

| 规则 | 定义 | 解释 |
|---|---|---|
| 零阈值（默认） | `A > 0` 为 advantage，否则 disadvantage | 与当前模型预期相比是否更好；A=0 明确归入非正类，不意味着真实动作一定更差 |
| 分位数阈值 | 参考数据上计算 `tau = quantile(A, 1-q)`；`A > tau` 为 advantage | 从参考分布选取较高优势样本，默认候选 q=0.3；分数可能仍小于零 |

两种规则统一采用严格 `>`，阈值相等时归入 disadvantage。保留 `score_sign=positive/zero/negative`，让零分和阈值标签可以区分。这个约定必须在元数据中记录；不要求与 RLinf 的阈值相等处理完全相同。

分位数默认使用 NumPy 的 `method=linear`，按有效帧等权计算。必须显式指定 train 参考集，记录其选择和哈希；不同 N 单独计算阈值。val/test 只应用已保存阈值，不参与拟合。若只用少量 train 轨迹拟合，报告明确写出“小样本参考阈值”。

同分样本可能使实际 advantage 比例偏离 q，不能随机翻转标签来凑比例。参考集为空必须报错。无效评分的标签为 null，并带原因，不得转成 disadvantage。不强制真实数据必须同时出现两类；分支覆盖用构造样例验证。

### F4：评分汇总与对比

提供以下可读结果：

1. 单轨迹：价值、优势随时间变化，advantage/disadvantage 色带、终止标记和有效跨度。
2. 轨迹汇总：有效/无效帧数、平均价值、平均优势、优势中位数及分位数、标签数量和比例、终帧价值、成功失败标记。
3. 分组汇总：按任务、采集批次、结局分组；分别报告按帧汇总与各轨迹等权汇总，明确分母。
4. 参数对比：同一价值预测下比较不同 N、零阈值和不同 q，查看标签变化数量与比例。
5. 两条或多条轨迹对比：优先同任务、同批次；支持实际秒数及归一化进度轴，并注明归一化进度不等于同一任务状态。

不设计没有依据的“综合能力分”或 0–100 成功概率。平均价值、平均优势和任务成功是不同指标；数值排序可以提供，但只能称为对应模型分数排序。不同任务、不同回报尺度、不同 checkpoint 的结果不能默认混合排名。

接管标记如有可显示为辅助色带；缺失时明确写“无接管标记”，不能将缺失当作全程未接管。接管不直接等于动作错误。

### F5：结果校验、缓存复用和重复运行

检查唯一键、完整覆盖、数值类型、轨迹边界、参数合法性、阈值来源及源文件身份。错误报告需包含数据集、轨迹、帧和失败原因。

同配置重复运行应得到相同标签，连续数值在声明的精度容差内一致。只更改阈值不触发模型推理；更改 N 复用价值但重新计算优势；更改 checkpoint、尺度或数据必须使相应缓存失效。

新输出默认使用新目录；已有目录身份不一致时拒绝覆盖。部分失败时不得留下可被当作完整结果读取的成功标记；临时文件写完校验后再原子替换。源数据、原奖励、划分和正式 checkpoint 均只读。

## 4. 输入与输出接口

### 输入要求

| 输入 | 必需内容 | 不匹配时 |
|---|---|---|
| 适配配置及合同 | 数据路径、任务、相机、gamma、失败奖励、return_scale、结果覆盖 | 报错，不猜测或重新估计尺度 |
| split / 轨迹选择 | 明确数据集和轨迹编号，完整轨迹范围 | 重复或不存在的键报错 |
| 价值 checkpoint | 当前受支持格式及实际配置 | 不兼容架构或缺失权重报错 |
| 原始图像与奖励 | 帧级对齐、可解码、合同修正后的奖励 | 缺帧或非有限值报错或显式 invalid，不静默跳过 |
| 标签配置 | 零阈值，或 q 与 train 参考选择 | 越界 q、缺失参考集报错 |

### 拟定输出目录

```text
artifacts/advantage/<run_id>/
  manifest.json          # 输入身份、模型/合同/数据哈希、参数、版本、阈值来源
  values.parquet         # 每个有效观察帧的价值与奖励
  scores.parquet         # 每帧、每个 N 的连续优势
  labels.parquet         # 每帧、每个 N、每套标签规则的条件标签
  thresholds.json        # 各跨度、标签规则的固定阈值及参考样本统计
  episodes.json          # 轨迹清单、结局、帧率和汇总
  comparisons.json       # 分组及参数对比
  validation.json        # 各项检查、失败信息和整体状态
  index.html             # 总览与筛选
  trajectories/          # 逐轨迹页面
  plots/                 # 可独立导出的 PNG
```

Parquet 为机器接口，JSON 为配置、汇总和检查接口，HTML/PNG 为阅读接口。无效数值使用可空列，不在 JSON 中写 NaN/Infinity。每种输出包含 `schema_version` 或由 manifest 明确约束版本。

### 逐帧字段合同

| 文件 | 关键字段 |
|---|---|
| values | `dataset_id:string, task_id:string, episode_index:int, frame_index:int, timestamp:float, fps:float, value:float, reward_raw:float, outcome:string` |
| scores | 上述唯一键，加 `horizon:int, effective_horizon:int, reward_sum_raw:float, reward_sum_normalized:float, value_current:float, value_next:float?, terminal_reached:bool, advantage_continuous:float?, valid:bool, invalid_reason:string?` |
| labels | 唯一键及 horizon，加 `label_set_id:string, threshold:float, score_sign:string?, label:string?, is_advantage:bool?` |

values 唯一键为 `(dataset_id, episode_index, frame_index)`；scores 再加 horizon；labels 再加 label_set_id。标签只允许 `advantage`、`disadvantage` 或无效时 null，且 `is_advantage` 与文本标签严格一致。人工标注 outcome 和模型 label 分列保存。

## 6. 自动测试与验收清单

### 手算基准

使用 gamma=1、S=4000：

- 成功轨迹 `r=[-1,-1,0]`，取其精确归一化累计回报 `V=[-2,-1,0]/4000`，N=1、2、10 时各帧优势应为 0。
- 失败轨迹 `r=[-1,-2000]`，取 `V=[-2001,-2000]/4000`，上述跨度的优势同样应为 0。失败结局不应被强行标成负优势。
- 两帧成功轨迹的起始帧，`V=[-0.2,-0.1]`、N=1 时 A=0.09975；`V=[-0.1,-0.2]` 时 A=−0.10025。用于覆盖正负标签。
- 最后一帧失败时 A=`-2000/4000 - V_last`；成功时 A=`-V_last`，检查失败惩罚未漏算或重复。

另测 N=0/负数拒绝、N 大于轨迹长度、不同数据集相同编号、缺帧、未确认截断、空参考集、NaN/Inf、阈值相等、全同分、全正/全负、不同 N 分别拟合阈值。核心公式可测试其他 gamma，但当前 checkpoint 合同不匹配的 gamma 不能用于正常运行。

## 7. 不作为本轮验收要求的事项

不要求正标签对应真实好动作、不要求失败轨迹平均优势更低、不要求优于简单对照、不要求成功率改善。当前模型是状态价值模型，优势也是依据观察轨迹估计的多步分数，不能宣称是精确的动作价值或因果贡献。

不要求补采数据、训练 π 模型、更换完整多模态 critic、统一所有 conda 环境或接入机器人。后续若要用标签训练策略，需另行验证信号可靠性、动作接口和训练消费逻辑。
